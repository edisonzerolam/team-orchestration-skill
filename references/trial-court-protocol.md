# 类审判庭协议（Trial Court Protocol）
> **现行补充协议（Trial Court Protocol）**：本文档为审判庭五阶段的**详细执行规范**（含案卷归档、自学习 S1/S2、终审意见书七段式、质证/回灌修订 Prompt 模板、二审终审制）。SKILL.md v3.4 五阶段为精简视图，执行复杂庭议时以此规范展开。

> ⚖️ **team-orchestration 核心运行机制 v2.5**
> 
> **自动触发条件**（满足任一即走审判庭五阶段）：
> ① 派出多于 1 个子代理；② main agent 与 ≥1 个子代理协作；
> ③ main agent 以多角度执行任务。
>
> 确保 **结论有依据、分歧有留痕、裁决可追溯**。

---

## 0. 核心原则

| 原则 | 说明 |
|------|------|
| **自动触发** | 满足任一条件（>1子代理 / main+子代理协作 / 多角度执行）→ 自动走审判庭五阶段 |
| **信息公开** | 每阶段产物对所有参与方可见，**裁决权唯一归 main agent（审判长）** |
| **资产即工具** | 子代理可调用 WorkBuddy 资产桥接层匹配到的 MCP 工具/连接器/技能作为举证手段 |
| **严禁虚构** | 所有依据必须真实可核验，存疑项如实标注"存疑/待核" |
| **全程留痕** | 每轮产物落盘到 `deliverables/trial/{docket_id}/`，供后续审计与自学习 |

---

## 1. 角色映射

| 司法类比 | 工程实现 | 由谁充当 | 职责 |
|---------|---------|---------|------|
| 审判长 | **main agent（主理人）** | 当前主 agent | 立案、控轮次、汇总产物、一审裁决、**二审终局裁决** |
| 举证方 | **子代理（正/反/中立）** | Agent 工具拉起的 general-purpose | 独立举证、质证他方、据反驳修正、提交产物 |
| 书记员 | main agent 兼任 | — | 记录每轮产物、归档审判记录 |
| 法警 | 资产桥接层 | Asset Resolver 自动 | 匹配并将可用资产注入子代理 prompt |
| 陪审团 | 自学习层 | — | 历史裁决记录影响未来匹配 |

## 2. 流程总览（五阶段 · 二审终审制）

```
Phase A: 立案 & 争点拆解（main 独任）
────────────────────────────────────
main: 议题登记 → 模糊度检测 → 争点提取 → 角色分配 → 资产匹配
→ 产出：DocketRecord + 争点清单 + ResolvedAssets
→ 落盘：deliverables/trial/{docket_id}/00-立案/

Phase B: 举证（子代理并行）
────────────────────────────────────
main: 同一消息并行拉起 2-6 个子代理
      每个 prompt 含：角色分工 + 举证要求 + 产物模板 + 可用资产
sub:  独立举证（可联网/调 MCP/用技能）
→ 产出：P{i}(A) 举证产物
→ 落盘：deliverables/trial/{docket_id}/01-举证/

Phase C: 质证（子代理并行）
────────────────────────────────────
main: 汇总 B 产物 → 打包分发给每个子代理
sub:  逐条质证他方 → 修正己方立场 → 再提交
→ 产出：P{i}(B) 质证产物
→ 可重复：争议未收敛时自动追加一轮（最多 2 轮）
→ 落盘：deliverables/trial/{docket_id}/02-质证/
→ 检查点（v3.5 · P0-4）：落盘后设检查点 `checkpoint_manager.py save --step C_cross_exam --state {docket_id, 轮数, 分歧数}`

Phase D: 一审裁决 + 回灌修订（main 裁决 → 子代理并行修订）
────────────────────────────────────
main: 逐条采信/排除 → 《一审判决书》（中间产物）
sub:  对判决逐条回应 + 立场再修订（固定 1 轮）
→ 产出：P{i}(C) 回灌修订产物
→ 落盘：deliverables/trial/{docket_id}/03-一审/ + 04-回灌修订/
→ 检查点（v3.5 · P0-4）：落盘后设检查点 `checkpoint_manager.py save --step D_revision --state {docket_id, 轮数, 分歧数}`

Phase E: 二审终审（main 独任，不回灌）
────────────────────────────────────
main: 终局裁断 → 《终审意见书》（二审终局）
      → 记录资产使用情况 → 触发自学习归档
→ 产出：终审意见书
→ 落盘：deliverables/trial/{docket_id}/05-二审终审/
→ 归档：deliverables/trial/archive/{yyyy-mm}/{docket_id}/
```

## 3. Phase A: 立案 & 争点拆解（详细）

### 3.1 主理人动作

1. **议题登记**：为本次议题生成 `docket_id`（格式：TC-{YYYYMMDD}-{序号}）
2. **模糊度检测**：用 5W2H 检测议题是否清晰。若模糊，向用户澄清（≤2 轮）
3. **争点提取**：拆解出 1 条核心争点 + 2-6 条子争点（每条子争点应可独立举证）
4. **角色分配**：根据争点数量和复杂度，分配举证角色：

   | 子代理数 | 角色分配 | 适用场景 |
   |---------|---------|---------|
   | 2 | 正方 / 反方 | 简单二分决策 |
   | 3 | 正方 / 反方 / 中立 | 有争议的权衡问题（默认配置） |
   | 4 | 正方 / 反方 / 技术专家 / 实务专家 | 需专业知识的争议 |
   | 5-6 | 主理人 + 4-5 个专业领域视角 | 跨领域复杂议题 |

5. **资产解析**：调用 Asset Resolver 匹配与议题类型相关的可用资产（MCP/技能/连接器/专家团）
6. **产出落盘**：写入 `00-立案/争点清单.md` + `00-立案/案卷信息.json`
7. **案卷 metadata（v3.5 · P2-1）**：`00-立案/案卷信息.json` 含 `resume_from`（上次完成阶段，由 checkpoint_manager 产出）与 `skipped_phases`（显式跳过记录）字段，供跨会话续审（P0-4）读取

### 3.2 资产解析锚点

```python
# 在 Phase A 结束时自动调用
assets = resolve_assets_for_issue(
    issue_type=extract_issue_type(sub_points),
    docket=docket_record
)
# 结果注入到 Phase B 子代理 prompt 的"可用资源"部分
```

## 4. Phase B: 举证（详细）

### 4.1 主理人动作

1. 收齐 Phase A 产物（争点清单 + 资产解析结果）
2. 对每个角色编写子代理 prompt（含角色分工、举证要求、可用资源、产物模板）
3. **同一消息内并行**发起 N 个 Agent 调用
4. 收齐后落盘到 `01-举证/P{i}(A).md`

### 4.2 子代理 Prompt 标准结构

```markdown
## 角色：{角色名}
你是本次审判庭的「{角色名}」，专业领域：{领域}

### 议题
{核心争点}

### 你的立场分工
{具体举证方向}

### 举证要求
1. 结论先行，然后展示依据
2. 每条依据必须标明来源（法条/文献/数据源/URL）
3. 严禁虚构，存疑标注"存疑/待查"
4. 这是第一轮举证，稍后你会收到其他方产物并需要质证
5. 自反证义务：每条结论必须自带 1 条最强反论并回应（缺失则该条 confidence 上限 0.6）

### 可用资源
{由 Asset Resolver 动态生成，见 `scripts/asset-resolver.py --snapshot`}
例如：
- 🛠 MCP 工具：通达信(查行情/财务)、腾讯自选股(查数据)
- 📦 技能：deep-research(深度调研)、fund-advisor-cn(基金分析)
- 👥 专家团建议：{推荐的专家团}

### 产物格式
## 产物 P{i}（阶段 B）— 角色：{角色名}
### 一、核心主张
### 二、举证依据（表格：| # | 依据/事实 | 来源 | 可信度 |）
### 三、自反证（最强反论 + 回应）
### 五、给审判长的裁决建议
```

> **自反证义务（v3.5 增强 · P0-5）**：每条结论自带最强反论并回应，缺失则该条置信度上限 0.6（回落到 cross-validation 的「单来源中等置信度」档）。

### 4.3 子代理动作

- 独立完成举证
- 可根据议题使用可用资源（MCP 工具查询数据、技能深度分析）
- 产出产物，通过 Agent 返回值回传 main

## 5. Phase C: 质证（详细）

### 5.1 主理人动作

1. 收齐所有 `P{i}(A)` 后，打包为完整上下文
2. 对**每个子代理**，再次发起 Agent 调用，prompt 含：
   - 他方全部举证产物（全文）
   - 质证要求：逐条指出他方依据的可信度/偏颇/遗漏
   - 修正要求：基于他方质证调整己方立场
3. 收齐后判断分歧是否收敛：
   - 分歧点 ≤ 1 → 进入 Phase D（一审）
   - 分歧点 > 1 → 自动追加一轮质证（最多 2 轮）
   - **收敛需独立证据（v3.5 增强 · P0-5）**：不能只看"多数一致"——多数方须有 ≥2 个独立来源支持才可判收敛；仅共识但单源 → 标「共识但单源」，进入一审时降低采信权重
   - **main 纪律（v3.5 增强 · P0-5）**：质证/回灌修订阶段，main 在举证收齐前不表达个人立场倾向，防信息级联引导子代理

### 5.2 质证 Prompt 标准结构

```markdown
## 阶段 C: 交叉质证 — {角色名}

你已经完成了第一轮举证。现在审判长把其他方的产物全部交给你。

### 质证要求
1. 对他方产物逐条质证：
   - 哪些依据可信？哪些有偏颇？
   - 哪些遗漏了有利于你方的事实？
2. 修正己方立场：
   - 撤回站不住的主张
   - 加强可坚守的主张
   - 补充新的反驳依据

### 其他方产物全文
{此处插入其他方全部举证产物}

### 产出格式
## 产物 P{i}（阶段 C）— 角色：{角色名}
### 一、对他方质证意见
### 二、己方立场修正
### 三、修正后的终局建议
```

### 5.3 交叉验证锚点

```
在质证过程中自动触发 Layer 1.5 交叉验证：
- 对每条多来源的主张检查来源独立性
- 单来源标注"中等置信度"
- 冲突点标注"分歧未收敛"
```

## 6. Phase D: 一审裁决 + 回灌修订（详细）

### 6.1 主理人动作（一审裁决，main 独任）

1. 汇总最新一轮 `P{i}(B)`（如有多轮质证，取最新一轮）
2. 对每条子争点**逐条裁断**：采信 / 部分采信 / 排除
3. 形成《一审判决书》（**中间产物**），结构见 6.2
4. 一审判决书落盘 `03-一审/first-instance-verdict.md`，流程中向用户展示摘要；**不单独交付、不停顿**（二审必审，不因一审结论被普遍接受而跳过）

### 6.2 一审判决书模板（中间产物）

```markdown
## 一审判决书 — {议题}

### 一、案卷信息
- docket_id: {编号}
- 议题：{原始议题}
- 审判日期：{日期}
- 参与方：{角色列表}

### 二、争点回顾
| 争点 | 正方主张 | 反方主张 | 中立观察 |
|------|---------|---------|---------|

### 三、逐条裁决（一审）
| 争点 | 裁决（采信/部分采信/排除） | 采信方 | 理由 |
|------|--------------------------|--------|------|

### 四、一审结论
{综合结论}

### 五、存疑/遗留事项
{如实标注未解决的问题}
```

### 6.3 回灌修订（子代理并行，固定 1 轮）

1. 把《一审判决书》全文 + 各方最新产物打包，对**每个子代理**再次发起 Agent 调用
2. 子代理产出 P{i}(C)：① 对一审判决逐条回应（服判/异议+理由）② 立场再修订 ③ 终局建议
3. **固定 1 轮**：不因收敛提前结束，也不追加第二轮
4. 收齐落盘 `04-回灌修订/P{i}(C).md`

### 6.4 回灌修订 Prompt 标准结构

```markdown
## 阶段 D: 一审回灌修订 — {角色名}

一审已结束。审判长把《一审判决书》和各方最新产物全部交给你，请为二审终审做最后一轮修订（固定 1 轮，修订后直接进入二审终审，不再回灌）。

### 修订要求
1. 对一审判决逐条回应：接受（服判）或异议（给出理由与依据）
2. 基于判决与他方产物修正己方立场：撤回站不住的主张 / 加强可坚守的 / 补充新的反驳依据
3. 注明相比上一轮的变更要点（变与不变）

### 一审判决书
{此处插入一审判决书全文}

### 其他方最新产物
{此处插入其他方最新质证产物}

### 产出格式
## 产物 P{i}（阶段D 回灌修订）— 角色：{角色名}
### 一、对一审判决的逐条回应（服判/异议+理由）
### 二、己方立场再修订说明
### 三、给二审审判长的终局建议
```

## 7. Phase E: 二审终审（详细）

### 7.0 终审前置门禁（v3.8 · TC-20260816-3）

进入 Phase E 前，main 必须满足「回声收齐或终止确认」：① 全部子代理本轮回声（P{i}(C) 回灌修订产物 + 完成通知）已收齐落盘；或 ② 经 `list_agents` 确认全部子代理已终止（ready、无运行中、不再产生新回声）。两者满足其一才可进入 7.1；仍有子代理运行且存在未收集回声时**不得**终审。

### 7.1 主理人动作（不再派发子代理）

1. 汇总全部 `P{i}(C)`（一审回灌修订产物）
2. 对每条子争点**逐条终局裁断**：采信 / 部分采信 / 排除（**禁止引入新论点**，以一审修订产物为界）
3. **先独立推导再引用（v3.5 · P0-1）**：终审写理由前，main 必须先就每个子争点写出自己的独立判断（不先看各方便利结论），再引用各方产物佐证/反驳——防止被多数方结论锚定
4. **五维 rubric（v3.5 · P0-1）**：对每条裁决理由按 5 维打分（依据充分性/来源独立性/论证逻辑自洽/与质证记录一致/对反证的回应，各 0-1 分）。任一维 ≤0.3 → 该条判 fail，**回退一审重审**（不跳过、禁止直接交付）
5. **位置交换自检（v3.5 · P0-1）**：开放题裁决前做一次"立场互换"推演（若采信反方，正方最强反驳是什么？），记录在终审意见书"裁决理由"备注列
6. 形成《终审意见书》（**二审终审 · 终局，不再回灌修订**），结构见 7.2
7. **独立复审/升级（v3.5 · P1-4）**：任一子争点置信度 <0.3（cross-validation 判定"不可信"）或整体重审 >2 次 → **不直接交付**，走独立复审（全新上下文子代理复核全案卷）或升级用户人工仲裁；留痕入案卷 06-资产使用记录/07-反馈记录
8. 终审结论作为 team-orchestration 主工作流"交付"环节的输入
9. 触发自学习归档（Layer S1+S2）

> **回退重审契约（v3.5 · P0-1）**：同一子争点最多 1 次回退；回退仅重做 main 侧独立裁决（**不重新回灌子代理**，保持 C2 固定轮次语义）；五维 rubric 全维达标后才进二审；重审次数写入案卷 `cross_exam` 字段。

### 7.2 终审意见书模板（二审终审 · 终局）

```markdown
## 终审意见书 — {议题}（二审终审 · 终局）

### 一、案卷信息
- docket_id: {编号}
- 议题：{原始议题}
- 审判日期：{日期}
- 参与方：{角色列表}
- 一审判决书：{引用 03-一审/first-instance-verdict.md}
- 所用资产：{资产清单}

### 二、争点回顾
| 争点 | 正方主张 | 反方主张 | 中立观察 |
|------|---------|---------|---------|

### 三、质证与一审修订记录
| 阶段 | 轮数 | 关键变更（变与不变） |
|------|------|---------------------|
| 质证 | {N} 轮 | {...} |
| 一审回灌修订 | 1 轮 | {...} |

### 四、逐条裁决（二审终局）
| 争点 | 裁决 | 采信方 | 理由 | 与一审异同 |
|------|------|-------|------|-----------|

> **结论层完整性门禁（v3.5 · P1-2）**：终审交付前校验——① 每条子争点（立案时拆出的 2-5 条）在"逐条裁决"表中都有对应行；② 每行裁决理由非空且含 rubric 维度引用（依据充分性/来源独立性/论证自洽/与质证一致/反证回应）；③ 遗漏/NA 子争点须显式标注并说明原因。由 `references/phase-gates.md` 检查清单承载。

### 五、终局结论
{综合结论，标注"二审终审，不再回灌"}

### 六、存疑/遗留事项
{如实标注未解决的问题}

### 七、资产使用评价
| 资产 | 类型 | 贡献度 | 下次建议 |
|------|------|-------|---------|
```

## 10. 质量门禁

- **终审意见书必须包含资产使用评价**（没用任何资产也要说明原因）
- **严禁在二审终审中引入新论点**（未在举证/质证/一审回灌修订中出现的主张不可采信）
- **每轮质证与一审回灌修订产物必须标注"相比上一轮的变与不变"**
- **终审结论的可信度 = 最低可信度依据的可信度**（最薄弱的证据决定整体质量）
